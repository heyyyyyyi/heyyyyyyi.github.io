blog from anthropic : https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

这篇blog是2026年初的作品，目前随着agent越发广泛深入地运用到行业中，想关的评价方向和方法当然有更多的拓展，但是这篇blog依旧有许多能够学习到的idea，或者说依旧并非所有开发都达到的标准值得深思。

blog里提到不同领域的agent有不同的评价方法，coding、chatting、research或者computer use，这些领域是最早开始拓展agent开发项目的，也是大家最早开始接受agent用不同标准衡量agent的方向。在这些类似于替代程序员、操作员、研究员的领域，既然JD里都有不同的标准，agent当然需要不同的侧重，blog里提到的方法都有共性，能够抽象出一套有具体计算方法的benchmark能够提供标准打分。扩展到目前不同的业务，这些标准可以放给产品部门做详细的设计，在agent开发中通过这些evaluation的结果迭代升级agent。当然这个过程中，对传统系统埋点统计、数据分析也是必不可少的，毕竟支持agent成为一个好用的工具乃至产品是一个系统级的项目，除了对智能（AI）的衡量，对稳定可靠性以及成本控制也是非常重要的。

blog里还有几点是anthropic的经验之谈，1.尽早开始设计数据集和评估任务 2. 构造均衡的习题集 3. 构建评估框架（自动定时运行、badcase沉淀或者我愿意称之为线上线下联动、评分器设计）“A complete picture includes production monitoring, user feedback, A/B testing, manual transcript review, and systematic human evaluation.” 4. 长期的使用和维护（version control）

这一直是agent开发的痛点：“修复一个故障、制造另一个故障”也是我之前提过很多次的点，在未来的开发中，agent version、evaluation version 同步维护，回归测试似乎逐渐成为大家的共识，但是如何在引进这么大一个不确定性的模型之后依旧尽力维护迭代升级的步伐将会是一个永久的问题。
