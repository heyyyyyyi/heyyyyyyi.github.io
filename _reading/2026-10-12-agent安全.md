paper from arXiv : https://arxiv.org/html/2607.14611v1

这篇文章不长，蛮有意思。主要讲的是对 memory 文件（例如 Claude 的 CLAUDE.md、Codex 的 AGENTS.md）发起攻击，效果类似传统 XSS 的持久化注入。读下来觉得有几点值得注意：

1. 越来越多的产品走向 AI native，agent 主导的架构越来越普及。大模型数据驱动的本性，也成了它原生的缺陷：数据是否可信、是否有偏，在不确定性的加持下都会带来很多变量。

2. 大家拥抱 AI native，很大程度上是因为它“可以迭代、自我升级”——用户和 agent 都能把经验沉淀为 skill、memory，甚至训练数据。文章点出的攻击面正在这里：用户和 agent 同时拥有文件的控制权，而自动化又弱化了人的监控角色，注入攻击就显得水到渠成。

3. 数据来源处于核心地位。当 agent 主要依靠一系列自然语言规则灵活行动时，这些规则的可靠性就直接关系到整个系统的安全。

4. 还有一个小点很有意思：文中提到 Opus 5.5 能力很强，能明确识别出漏洞，但倾向于提示用户，而不是直接清除，当更换为haiku之类稍弱的模型之后攻击成功了。这意味着，当我们习惯了更强的模型，一些能力会被当作常态而被忽略。环境不变、换了模型之后，留下的“残局”可能是弱一些的模型处理不了的——像留下一套过重的盔甲，以前运行流畅、无虞的地方，换了模型就可能出现漏洞。

   类比一下，也可能有这样的情况：模型习惯把某些安全提示记录在某个位置，环境变化后，它在新环境里找不到类似提示，于是跳过这一步，同样可能导致出错甚至安全问题。

而当前 LLM 迭代的速度，又推着大家不停地适应和更换模型，甚至同一个模型自身的能力和习性也在动态变化。这一点在设计 agent 系统时，值得一直放在心上。
